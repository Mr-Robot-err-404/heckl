PR Detail - Review (diff)
--------------------------
[ ] File tree sidebar
[ ] Concern lifecycle: open / resolved / dismissed / superseded
[ ] Changes since last agent review - GitHub's "changes since your last review",
    but keyed to the agent session rather than a human. Diff the PR head against
    the head sha the last completed session ran on, so a re-review shows only
    what moved. The sha is already recorded (worktree paths are
    {pr}-{sha}), so the anchor exists; the work is a second diff fetch
    (compare base..head between two shas), a toggle in the diff header, and
    deciding what happens to existing concerns pinned to lines that the new
    diff no longer contains - which overlaps the concern lifecycle item above.
    Force-pushes are the sharp edge: the old sha may be unreachable, in which
    case fall back to the full diff rather than erroring.

Onboarding / packaging
-----------------------
[x] Single `heckl` binary - setup, doctor, serve, migrate
[x] TOML config from a commented template, XDG paths, HECKL_CONFIG
[x] Device-code GitHub login, token at 0600; gh demoted to a fallback
[x] Preflight checks shared by `doctor` and `serve`
[ ] Bundle .opencode/agents and tools into the binary - opencode.project_dir
    only exists because the agent and tool files must be on disk next to a
    checkout. embed + write to a state dir on setup would kill the whole
    class of "wrong project_dir" failures, but the session deep link is
    base64 of that same dir, so both have to move together
[x] report.ts is import-free - no npm anywhere in the bundle. It used to
    import @opencode-ai/plugin, whose tool() is identity and whose
    tool.schema is a bare zod re-export. opencode's ToolRegistry only takes
    the zod path when every arg value has _zod on it; otherwise it builds
    the JSON Schema itself from plain objects. args are now plain JSON
    Schema, so bundle.Write produces a tool that loads in any project dir.
    The tradeoff: opencode no longer validates args before execute, which is
    fine because reviewer.go unmarshals them into reviewOutput regardless.
[ ] Capabilities endpoint - the UI cannot tell tmux is disabled or missing, so
    the button is offered and then fails. Needs /api/capabilities plus a
    frontend that respects it
[ ] `serve` does not re-check the token against GitHub, only that one exists.
    An expired token surfaces as a 401 on first use, not at startup
[ ] No systemd unit or `--daemon`; nothing keeps it running across reboots
